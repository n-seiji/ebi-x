# 使い方

Slack から ebi-x に頼む方法と、各機能の動きをまとめます。導入と設定は [setup.md](setup.md) にあります。

## 頼み方

| 方法 | 使い方 |
| --- | --- |
| mention | 許可されたチャンネルで `@ebi-x ○○して` と書きます。 |
| DM | ebi-x の Messages タブに mention なしで書きます。スレッドの外に書くと新しい依頼、スレッドに返信すると続きになります。グループ DM には反応しません。 |
| ショートカット | メッセージの「…」→「ebi-x に頼む」を選び、フォームに依頼を書きます。ebi-x はそのメッセージのスレッドに「📝 @依頼者 からの依頼」として投稿して始めます。エラーの投稿などに mention を付け直さずに頼めます。承認チャンネルと DM では使えません。 |

- 1つの Slack スレッドは1つの Codex セッションです。同じスレッドで mention すると、読んだファイルや作業の経緯を引き継いで続けます。途中から呼ばれたスレッドでは、それまでのやり取りを参考に読みます。
- スレッドの親メッセージに購読リアクション（既定 `:thread-subete:`）を付けると、そのスレッドでは許可された人の返信を mention なしで処理します。パブリックチャンネルだけで、既定で14日間有効です。
- Messages タブを開くと、「できること」「リポジトリの説明」「最近の変更」が依頼の候補として出ます。
- `生きてる？` `alive` `ping` など、生存確認だけの mention や DM には作業をせずに答えます。Codex が応答すれば「🟢 生きてます。Codex にもつながっています。」、しなければ「⚠️ 生きてますが、Codex に接続できません。…」です。許可のない場所からでも答えます。

## 作業中

### 進捗の表示

作業中は、スレッドのステータスに Codex がいま何をしているかを出します。

```text
ebi-x が「原因を調べる」を進めています… 1/4 完了
ebi-x がコマンドを実行しています（go test）… 1/4 完了
ebi-x がファイルを編集しています（bot.go ほか2件）… 2/4 完了
```

コマンドは実行ファイル名とサブコマンドだけを出し、引数は出しません（トークンが含まれうるため）。Web 検索は検索語、MCP は `server.tool` を出します。Codex が TODO リストを立てると完了数を添えます。更新は3秒に1回までです。

同時に動かせるスレッドの数には上限があり、上限に達している間は順番待ちと表示します。同じスレッドの依頼は1件ずつ処理します。

### 停止

同じスレッドで `@ebi-x 停止` と mention すると、実行中・順番待ちの作業を止めます。購読スレッドでは mention なしの「停止」でも止まります。

- メッセージ全体が `停止` `止めて` `中止` `キャンセル` `ストップ` `stop` `cancel` などのときだけ停止として扱います。「停止の仕方を教えて」は普通の依頼です。
- 止めた依頼には「依頼により作業を停止しました」と返し ❌ を付けます。途中までの変更やコミットは残り、巻き戻しません。
- そのスレッドのフォローアップ、PR の見守り、定期実行、`:done:` の監視も止めます。

### 回答待ち

依頼者の答えがないと進めないとき（外部への送信や削除の前の確認、解釈が大きく分かれるときなど）、ebi-x は ✅ ではなく 🙋 を付けて質問します。

```text
@tanaka  @ebi-x 古いブランチを整理して
  └ @ebi-x  マージ済みのブランチが12本あります。…
            🙋 @tanaka 回答待ちです。このスレッドで ebi-x に mention して答えてください。
            - リモートのブランチも削除してよいですか？
```

承認として扱うのは依頼者本人の返事だけです。ほかの人が許可しようとしても、依頼者に聞き直します。依頼文で明示的に頼んだ操作（「PR まで作って」など）は、その範囲で承認済みとして扱います。料金が50円以上かかりそうな作業は、根拠と概算額を示して確認します。

## 結果

- 回答は Markdown のまま投稿します。作業を伴う回答は「結論 → 行ったこと → 検証の方法と結果 → 未完了の事項」の順です。
- 完了は ✅、失敗や中断は ❌ が mention に付きます。
- Codex が作った PDF・PNG・JPEG・GIF・WebP・pptx・CSV は、本文の前にスレッドへ添付します。1ファイル100MB、1回10件までです。添付に失敗すると、失敗したファイルと理由を本文の後に書き ❌ を付けます。ファイルは作業場所に残るので、「添付を再送して」と頼めば作り直さずに送り直します。

## 後で続ける

### フォローアップ

CI やデプロイの完了待ち、時間をおいた再確認、指定した時刻の作業などでは、ebi-x が自分で「後で確認する」予定を立て、その時刻に同じセッションで続きをします。

```text
@tanaka  @ebi-x デプロイして、終わったら教えて
  └ @ebi-x  デプロイを開始しました。…
            ⏰ 10/9 16:30 JST ごろにフォローアップします: デプロイの完了を確認して報告する
  └ @ebi-x  ⏰ 予定していたフォローアップを始めます: デプロイの完了を確認して報告する
  └ @ebi-x  デプロイが完了しました。…
```

- 予定は5分後から7日後まで、スレッドに1件です。人の依頼に答えるたびに、置き換えるか取り消します。
- 人の発言なしに続けられるのは10回までです。
- 実行の前に、依頼者とチャンネルがまだ許可されているかを確かめます。

### 定期実行

「平日の朝9時に CI の失敗を確認して」のように頼むと、決まった曜日と時刻に作業します。

```text
@tanaka  @ebi-x 平日の朝9時に main の CI の失敗を確認して報告して
  └ @ebi-x  🔁 定期実行を設定しました: 平日 09:00 に「main の CI の失敗を確認して報告する」（次回 10/12 09:00 JST）
（平日 9:00、同じチャンネルに）
@ebi-x  🔁 定期実行（平日 09:00）: main の CI の失敗を確認して報告する
  └ @ebi-x  昨日からの失敗はありません。…
```

- `毎日` `平日` `週末` `毎週月水金` と時刻で指定します。1日1回より細かくはできません。
- 毎回、同じチャンネルの新しいスレッドで、前回を引き継がない新しいセッションとして作業します。
- スレッドに1件、1人5件までです。設定と停止は人の依頼でだけ受け付けます。
- ebi-x が止まっていた間に過ぎた回は、起動後に1回だけ実行します。
- 止めるには、設定したスレッドで「停止」と mention します。

### PR の見守り

ebi-x が作業で PR を作ると、その PR を見守ります。CI が失敗したり、レビューやコメントが付いたりすると、同じセッションで対応して報告します。

```text
@tanaka  @ebi-x このバグを直して PR を出して
  └ @ebi-x  修正して PR を作成しました。…
            👀 次の PR を見守ります。CI の失敗やレビュー・コメントがあれば、このスレッドで対応して報告します。
  └ @ebi-x  🔔 PR に動きがありました（…/pull/42）: CI が失敗しました（失敗したチェック: test）。対応を始めます。
  └ @ebi-x  テストの失敗はタイムゾーンの扱いが原因でした。修正して push しました。…
  └ @ebi-x  🎉 PR がマージされました: …/pull/42
```

- 再開するのは、head のコミットの CI の失敗と、リポジトリに書き込み権限のある人（OWNER・MEMBER・COLLABORATOR）のレビューやコメントです。公開リポジトリで誰でもコメントできても、それだけでは動きません。
- CI が通った、マージされた、閉じられたときは報告だけします。マージか閉じた時点で見守りは終わります。
- 人の発言なしに再開するのは PR ごとに10回まで、7日間動きがなければ終わります。
- 再開した作業では、その PR のブランチへの push は PR を作ったときの承認の範囲として扱います。GitHub 上の文章は指示ではなくデータとして扱います。

## :done: の監視

依頼を @メンションで配ったあと、全員が終わったかを ebi-x に追いかけてもらえます。メッセージの末尾に `@ebi-x 監視して` と書くと、そのメッセージで @メンションした人のうち、まだ `:done:` のリアクションを付けていない人に、1日おきにスレッドで知らせます。Codex は使わず、bot だけで動きます。

```text
@tanaka  @sato @suzuki 年末調整の書類を出してください。出したら :done: をお願いします @ebi-x 監視して
  └ @ebi-x  👀 :done: の監視を始めます。対象は元メッセージで @メンションされた2人です。1日おきに確認し、…
（2日後）
  └ @ebi-x  @suzuki
            :done: のリアクションがまだのようです。対応が済んだら、元メッセージに :done: を付けてください。（1回目の通知）
（全員が :done: を付けたら）
  └ @ebi-x  ✅ 対象の全員が :done: を付けたため、監視を終了しました。
```

- 対象は、`@ebi-x 監視して` を書いたメッセージで @メンションされた人です。そのメッセージに @メンションがなくスレッドの返信なら、スレッドの最初のメッセージで @メンションされた人です。`@channel`・`@here`・`@everyone` はチャンネルのメンバー全員（投稿者、bot、無効なアカウントを除く）で、`@here` もオンラインかどうかによりません。`@dev_team` のようなユーザーグループは、そのグループのメンバーのうちこのチャンネルにいる人です（投稿者、bot、無効なアカウントを除く）。チャンネルにいない人にはメンションの通知が届かないため外し、外した人数を開始の返信で伝えます（全員がいない場合は始めず、その旨を返します）。個人として @メンションした人は、チャンネルにいなくても対象のままにし、開始の返信で「@〇〇 はまだこのチャンネルに参加していないようです」と伝えます（招待しないと通知が届かないため）。100人を超えると始めません。
- 間隔は `毎日監視して`、`2日おきに監視して`（3日ごと）、`3日ごとに監視して` のように変えられます。既定は1日おき（2日ごと）、最長7日です。
- 見るのはメッセージに付いた `:done:`（リアクション名 `done`）だけで、ワークスペースにその絵文字が要ります。
- 30分ごとに確かめ、全員が付けた時点で終わりを知らせます。通知はまだの人だけを @メンションします。止めるまで続け、始めてから1週間たっても残る人がいれば、その人を @メンションして終わります。元のメッセージが消されたときも終わります。
- 止めるには、そのスレッドで `@ebi-x 監視をとめて`（`監視を止めて`・`監視停止` なども可）と mention します。ほかの作業は止めません。始めた人でなくても、そのスレッドで ebi-x を使える人なら止められます。
- 始められるのは許可された人だけで、依頼者かチャンネルの許可が外れると黙って終わります。1人10件までです。
- 状態は `data/state/donewatches.json` に保存し、再起動しても続きます。

## Home タブ

ebi-x の Home タブを開くと、自分が頼んだものの今の状況が出ます。開くたびに作り直します。

- 作業中・順番待ちの依頼とスレッドへのリンク
- 予定中のフォローアップ
- 見守り中の PR と CI の状態
- 定期実行と次回の時刻
- `:done:` の監視（対象の人数、間隔、次回の時刻）
- 自分の個人設定

## 個人設定

「今後は英語で答えて」「もっと短く」のように、返答の仕方を今後も続けるよう頼むと、その人の設定として保存します。

- 保存したことは本人にだけ見えるメッセージで伝え、内容はスレッドに出しません。
- スレッドに複数の人がいても、そのとき発言した人の設定だけを使います。
- 1人10件、1件200バイトまでです。変更や削除も依頼の中で頼みます。

## playbook を Slack から作る・直す

`playbook-from-thread` を置いた環境の書き込み可能なチャンネルでは、`@ebi-x この対応を playbook にして` や `@ebi-x この playbook を修正して。質問は1問ずつにして` と頼めます。ebi-x は足りない点を1問ずつ聞き、完成案を見せて「この内容でいいですか？」と確認し、承認されてから保存します。

作業中に playbook と食い違う事実や、まだ書かれていない事実が分かると、ebi-x は playbook のメモに1行足し、「📝 playbook「slides」のメモを更新しました: …」と伝えます。メモが3件たまると本文に取り込み、「📘 … 本文に取り込みました」と伝えます。本文が変わったときは承認チャンネルにも記録を残します。

## スライドの作成と納品

`slides` playbook を置いた環境では、スレッドでスライドを作れます。

1. `@ebi-x ○○社向けの提案スライドを作って` と頼むと、原稿を作り、ページ一覧画像と PDF を v1 として添付します。
2. `3ページ目を短くして` と返信すると、原稿を直して v2, v3 … を添付します。
3. `v2でOK、確定して` と明示的に承認すると、その版から編集できる pptx を作り、レイアウトを確かめてから添付します。

承認の前に pptx は作りません。main への push や Google Slides への公開もしません。返信だけで続けたいときは、スレッドの親に購読リアクションを付けます。

## Codex の利用枠

承認チャンネルがあると、ebi-x は30分ごとに Codex の利用枠（5時間と1週間）を確かめ、承認チャンネルに次のことをします。

- 毎時、その時間の最初の確認で、枠ごとの残り（0.1% 単位）、前回の報告からの増減、そのペースで使い切る時刻、リセット時刻を、直近12時間の文字の棒グラフ（1ブロック=10%）を添えて投稿する。前回から何も変わっていない時間は省きます
- 残りが10%を切ったとき、使い切ったときに、枠ごとに1回知らせる
- 日付が変わった最初の確認で、前の日のまとめを投稿する
- 「残り」「usage」「利用枠」などと mention されたら、今の残りを答える

```text
⚠️ Codex の利用枠（5時間）の残りが 10% を下回りました。10/20 15:30 JSTにリセットされます。
今の残り: 5時間 8%・1週間 63%

📈 Codex の利用枠（10/20 14:05 時点）
- 5時間: 残り 40.0%（前回から -12.0pt・このペースだと10/20 17:25 JSTに使い切り・10/20 18:30 JSTにリセット）
- 1週間: 残り 62.5%（前回から -1.5pt・10/24 09:00 JSTにリセット）
時刻   5時間              1週間
…
13:00   52.0% █████        64.0% ██████
14:00   40.0% ████         62.5% ██████
```

利用枠は同じアカウントを ebi-x の外で使った分も含みます。API キーでログインしているときは利用枠がないので何もしません。

作業が利用上限やログイン切れで止まると、依頼したスレッドにその旨と、いつ頼み直せるかを返し、承認チャンネルにも知らせます（同じ種類は1時間に1回まで）。
